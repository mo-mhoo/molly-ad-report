2026-08-12，幫毛孩時代免疫力素材做「互動CTR × BTL ROAS」綜合跑分排序時，直接硬算會被小樣本雜訊主導，用戶認可以下兩個修正為正確方法，要求記錄為廣告分析知識，之後同類素材評分都要套用。

**問題現象：** 素材通過「ATL互動測試 → BTL轉換驗證」兩階段漏斗後（見 [[feedback_atl_btl_testing_logic]]），若直接用「互動%」和「ROAS」兩個原始數字加權跑分，會出現兩個嚴重失真：
1. 只成交1單卻ROAS虛高的素材（例：僅1單卻7.46x）排名衝到前面，但1單完全不能代表已驗證，是雜訊不是訊號。
2. 用「這批素材裡最低的ROAS」當0分地板（純min-max正規化）會把真正賺錢的素材（例：ROAS 2.6x，已經打平之上）硬算成0分，只因為它剛好是這批裡最低——同時也讓分數無法跨期比較（換一批素材，同樣ROAS換算出的分數會不一樣）。
3. 真正的大樣本現金牛（例：12單、收益$30,255，ROAS 4.24x）因為ROAS數字不是全場最高，會被小樣本雜訊素材壓到後面，排名不能反映它才是最可信賴的validated結果。

**正確算法（兩個修正）：**
1. **ROAS 做貝氏收縮（Bayesian shrinkage）**：`adj_roas = (purchases × roas + K × pooled_roas) / (purchases + K)`，K取3（可依樣本規模調整）、pooled_roas是該批所有已成交素材的總收益/總花費（加總後的整體ROAS，不是簡單平均）。樣本越小，adj_roas越被拉回整批平均值；樣本越大（例如12單），adj_roas幾乎等於原始值不太受影響。
2. **ROAS 分數用絕對刻度、不是批次內互比**：不要用這批素材自己的min-max（避免「矬子裡拔將軍」或「賺錢的素材因為是批次最低被打0分」）。改用業務意義上的絕對錨點，例如 1x（打平）= 0分、6x（優秀）= 滿分，中間線性內插、超過上限則封頂100分。這樣分數才有絕對意義，換一批素材、換一個期間都可以直接比較。
3. **互動CTR分數維持相對排名（min-max within batch）即可**——因為互動CTR本來就是「篩選機制」而非絕對業務指標，本無客觀絕對標準，適合用相對排名。
4. **綜合分＝ 30%互動分 + 70%ROAS分**——ROAS 權重較高，因為那才是漏斗跑完後真正驗證出的商業結果，互動只是前段的篩選/領先訊號。
5. **0單（尚未成交）的素材 ROAS分＝0，並標註「無成交」而非「低ROAS」**——語意上要跟「已驗證但效率普通」分開，避免使用者誤讀成「這支素材差」，其實只是「BTL還沒測」。
6. **1單的素材要额外標註「樣本極小」**，即使收縮後分數仍偏高，也要讓使用者知道信心水準低，不能當結論。

**呈現方式（2026-08-12 定案）：**
- 換算成星等一律用**10顆星**（分數/10，四捨五入到0.5顆星），不要用5顆星——5顆星精度砍半，會把本來分數不同的素材壓成同一個星等（實測：3支不同分數的素材在5星制下全變成★★☆☆☆，10星制才能分出4.5/4.0/3.5的差異）。一開始做過5顆星版本，使用者比較後主動要求改回10顆星，10顆星才是最終定案。
- 維持「絕對刻度」精神——不能為了讓這批最高分湊到10顆星而重新正規化，滿星本來就該很難拿到，這是刻意設計不是bug。
- **星等要獨立成一行**，不要跟素材名稱、ATL/BTL的chip數據擠在同一行——這是使用者在意的排版重點，原因是星星字元橫向很佔空間，跟其他數字擠在一起會讓那一列看起來很長很亂。放在標題下面、原本的 metrics-row chip 之上，當作一個獨立的評級小標籤。
- **視覺樣式要跟著承載的文件走，不要自己發明一套配色**——不管是放進 HTML 報告（用該報告既有的 CSS 變數：`--accent`當星星顏色、`--border`當空星顏色）還是放進簡報（用該簡報既有的主色、字體），星等的呈現都要用宿主文件本來的配色系統，不要為星等單獨設計一套跟主體不搭的視覺。

**How to apply:** 之後任何「素材成效綜合排序/跑分」的請求（不限免疫力/毛孩時代，凡是 ATL互動測試→BTL轉換驗證兩階段漏斗跑出來的素材評分），預設套用上述算法，不要用naive的min-max或直接乘積跑分。可換算成星等呈現時比照同樣的絕對刻度換算方式。相關：[[feedback_atl_btl_testing_logic]]、[[feedback_creative_report_template]]、[[project_ads_optimization_training]]。
