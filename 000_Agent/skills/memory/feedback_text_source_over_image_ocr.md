2026-08-14，整理御熹堂 Meta 素材切角命名時，我從螢幕截圖/口語轉述整理出「鄭崴云醫師」「林美齡」這兩個信任元素人名，被 Molly 當場糾正：正確是「鄭鈞云醫師」「代言人林美貞」，並明確說「你不要用圖片解析會錯字」。（2026-09-11 補充修正：這則記憶原本誤記為「鄭均云」，已比對 Meta 帳號實際廣告名稱＋ Molly 2026-09-11 再次確認，正確字是「鈞」不是「均」，特此更正——連記憶本身都要小心錯字傳染。）

**Why:** 中文人名有很多形近字（崴/均、齡/貞），圖片 OCR 或憑印象轉述時很容易讀錯，尤其在做「素材命名標準化」這種目的就是要收斂同一人統一寫法的任務時，人名一旦錯了會產生新的碎片標籤（同一人被拆成兩個不同標籤），完全違背任務初衷。

**How to apply:** 涉及人名、專有名詞、代言人名這類「打錯字代價高」的資訊，優先順序：
1. 直接文字資料源（API 回傳的 JSON/text、試算表儲存格文字、程式讀出的原始字串）— 最可信，因為是機器精確傳輸的文字。
2. 使用者截圖 — 可以用，但辨識完必須先列出整理好的文字給使用者核對過一遍再視為定案，不確定的字要明確標記出來問，不要自己猜著填。
3. 不要單憑截圖「印象」或口語轉述直接寫進最終文件/命名規則裡，沒有核對來源就當作定案。

適用範圍不限於人名，任何「錯字代價高」的欄位（料號、金額數字、網址）遇到截圖來源時都要走同一套「先列出來核對、不確定就標記」流程。
