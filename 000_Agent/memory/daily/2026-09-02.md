## 做法筆記

- 這次意外進入了 Plan Mode（系統自動切換，非用戶主動要求），照流程把已查到的 GA4 數據跟要改的 section 直接寫進 plan 檔給 Molly 看過再執行，而不是先執行再補計畫——這樣 Molly 能在改報告前就看到「(not set)退潮」「134155停留時間回升」這些關鍵發現，避免報告內容跟她預期不符才發現。
- GA4 查詢用 `landingPage`（不含 querystring）維度而不是 `landingPagePlusQueryString`，後者會因為每個 fbclid 追蹤參數不同而把同一篇文章拆成上千筆不同列，一次查詢輸出到 2.6MB（超過 Read 工具 256KB 上限），改用 `landingPage` 後乾淨很多，之後查文章層級流量都要記得用這個維度。
- Artifact republish 時，讀回來的舊版 HTML 開頭會夾帶平台自動注入的 `frame-runtime` script（`<!doctype html><html><head>...`）跟結尾的 `</body></html>`，直接複製整份拿去 republish 會被平台的 wrapper 重複包一層。要先用 python 從 `<title>` 開始截斷、砍掉結尾 `</body></html>`，只留作者寫的內容再 publish，跟 Artifact 工具規則「不要自己包 DOCTYPE/html/head/body」一致。
- 原報告的四段趨勢 bar 圖是「每一行（文章）自己的最大值 scale 到 56px」的邏輯，不是全局共用比例尺，加第四個資料點時要先抓該行原本最大值有沒有變（沒變就其他三根高度不用動，只算新的第四根）。
