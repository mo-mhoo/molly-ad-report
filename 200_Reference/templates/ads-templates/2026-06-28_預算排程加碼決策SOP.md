# 預算排程加碼決策 SOP

> 建立日期：2026-06-28
> 適用帳號：毛孩蝦皮（目標ROAS = 4）；其他帳號請自行設定目標ROAS

---

## 核心邏輯

Meta 預算排程（budget_schedules）對學習期的干擾遠低於直接調整日預算，因此可以比手動調預算更積極使用。

---

## 決策樹

### 第一層：落後指標（ROAS）

**今日活動 ROAS ≥ 1.5× 目標 ROAS？**

- e.g. 目標 ROAS = 4 → 今日需 ≥ 6
- CPA 明顯低於目標亦適用

#### YES → 直接加碼（不需看領先指標）

| 今日 ROAS / 目標 ROAS | 建議加碼% |
|----------------------|---------|
| 1.5 – 3×             | +50 ~ 100% |
| 3 – 5×               | +100 ~ 200% |
| 5×+                  | +200 ~ 800% |

> 以上即最終加碼 %，直接套入排程，上限 800%

---

#### NO → 領先指標評分（ROAS 持平或偏差時）

**評分項目（滿 2 分）：**

**① 加車指標（+1 / +0.5 / 0）— 條件式**

```
加車成本 YoY < 0%（比去年同期便宜）
  ├── YES → +1.0  ✅ 強信號：算法找到便宜的意向受眾
  └── NO  → 購物車率 YoY > 0%（比去年同期高）
               ├── YES → +0.5  ⚠️ 中信號：量好但成本偏貴
               └── NO  → +0    ❌ 兩者皆差，無加碼依據
```

**② 花費進度比（+1 / 0）**

```
花費進度比 = (今日花費 ÷ 日預算) ÷ (當前小時 ÷ 24)

≥ 1.0（超前或同步） → +1  算法吸收能力足，值得放量
< 1.0（落後進度）   → +0  不扣分，不加分（落後不代表算法差，可能是時段問題）
```

**評分結果 → 加碼幅度：**

| 總分 | 加碼% | 說明 |
|------|------|------|
| 2.0  | +50% | 三項全中，強信號 |
| 1.5  | +30% | 加車中信號 + 花費同步 |
| 1.0  | +20% | 單一強信號 |
| 0.5  | 觀望  | 信號不明確，下次載入再評 |
| 0    | 不加碼 | 效率差且意圖弱，考慮縮碼 |

---

## 設計原則

1. **ROAS 是效率指標，不是量能指標**
   - 同樣 ROAS=5，訂單 3 筆 vs 20 筆代表完全不同的放大空間
   - 花費進度比才是「算法有沒有在高速吸收」的信號

2. **加車成本 YoY 優先於加車率**
   - 成本下降 = 算法找到更多便宜的意向用戶 → 直接信號
   - 成本上升但率提升 = 量好但貴 → 需要謹慎的中信號

3. **花費進度比只加分不扣分**
   - 落後不代表算法差（可能是上午時段本來就慢）
   - 但超前代表算法正在高速吸收，值得給更多空間

4. **預算排程低風險**
   - 排程是預告式臨時加碼，Meta 不視為策略改變，學習干擾小
   - 就算加碼幅度較大，算法在沒有好機會時也不會強制花掉

## 數據來源

| 指標 | 來源 |
|------|------|
| 今日 ROAS | 新增排程 tab — 今日成效 |
| 目標 ROAS | 帳號設定（毛孩蝦皮 = 4） |
| 花費進度比 | 今日花費 + 日預算（排程 tab 已有）+ 當前時間 |

| 購物車率 YoY | 週報 BTL 轉換漏斗 — 點擊→購物車率 YoY% |
