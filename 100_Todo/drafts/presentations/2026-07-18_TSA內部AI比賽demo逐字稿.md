**作品：** Meta 廣告戰情室（`app.py`，Streamlit，molly-ad-report.streamlit.app）

## 二、逐字稿正文

### 開場鉤子（0:00-0:20）
> 「廣告的 ROAS 每天都在變動，今天表現好的活動，明天可能就掉下去。傳統做法是要打開 Ads Manager，一個帳戶一個活動去看數字，看到問題了，還要再點進去手動改預算——這中間的時間差，可能就是白花的預算，或是錯過加碼衝量的機會。
>
> 所以我做了一個工具，把『看數據』跟『動手調整』這兩件事，壓縮到幾秒鐘內就能做完。」

### 一句話定位（0:20-0:35）
> 「這是我自己開發的『Meta 廣告戰情室』，串接 Meta 廣告後台 API，可以即時看到所有帳戶、所有活動的表現，而且可以直接在這個畫面上批次調整預算，不用切去 Ads Manager。現在直接示範給大家看。」

*（切到畫面）*

### Demo①：成效快速 Overview（0:35-1:15）
**操作：** 選帳戶（毛孩時代／御熹堂）→ 選日期區間（示範用「過去 7 天」快捷鍵）→ 畫面秒出成效總覽卡片 → 往下帶一眼 ATL/BTL 漏斗。

> 「我選一個客戶帳戶，選時間範圍——就這樣，花費、轉換、ROAS 全部跳出來，還自動幫我比較上週、上月、去年同期，紅字綠字直接告訴我是變好還是變差。往下拉，還能看 ATL、BTL 轉換漏斗，一眼知道問題是卡在曝光、點擊，還是最後的購買轉換。」

### Demo②：快速加減碼（1:15-2:30，主秀）
**操作：** 切到「快速加減碼」分頁 → 點「載入／重新整理」→ 秀出活動列表（自動依今日 ROAS/7天 ROAS 排序，🟢/⏸ 狀態一目瞭然）→ 用「選🟢有花費」快速選取，或手動勾幾個活動 → 示範點擊 +25% 或 −25% 快捷按鈕，即時看到「舊預算 → 新預算」的成功訊息。

> 「重點來了。這邊會把這個帳戶下所有活動抓出來，自動依照『今日 ROAS』排序——表現最好的活動排最前面，表現差的排後面，還會秀出今日花費、今日 ROAS、7 天 ROAS、CPA、轉換價值這些關鍵指標，一眼就看得出誰在賺、誰在燒錢。
>
> 接下來，我可以直接在這個畫面勾選我要調整的活動——比如說，這幾個今天 ROAS 表現特別好的，我要幫它加碼。勾選、點『+25%』——大家看，它直接呼叫 Meta 後台 API，預算馬上從多少變成多少，立即生效，不是排程，是現在馬上生效。
>
> 表現不好的活動也一樣，勾一勾、點『−25%』，馬上停損。整個過程，不用開 Ads Manager，不用一個個進到活動裡面改，選好、按一下，全部活動一次批次搞定。」

### 效益總結（2:30-3:00）
> 「以前要調整多個活動的預算，得一個一個點進 Ads Manager 改，光是切換頁面、確認每個活動的數字就很花時間。現在因為可以一次看、一次批次調整，這樣算下來，一週至少可以省下 **1~1.5 小時**，而且是同時管理毛孩時代、御熹堂兩個客戶、多個帳戶都適用。反應速度快，就能少燒冤枉錢、也能更快抓住表現好的機會加碼衝量。」

### 結尾（3:00-3:15）
> 「這套工具目前是我自己每天在用，但這個『即時看數據＋一鍵動手調整』的架構，其實可以套用到任何需要盯著即時數據做決策的工作。如果大家手上也有類似的需求，很歡迎會後找我聊。謝謝大家！」

---

### Bonus（時間夠、5 分鐘版才加，約 30-35 秒）：預算排程
**操作：** 切到「預算排程」分頁，示範新增一個排程（不用真的送出，示範到填表畫面即可）。

> 「除了『現在馬上調整』，這邊也可以『先排定』未來的加碼時段——比如說我知道週末流量會比較好，可以提前設定好週六幾點自動加碼多少 %，不用真的守在電腦前手動點。」

## 三、Q&A 準備小抄

| 可能被問 | 簡短答法 |
|---|---|
| 資料安全嗎？會不會外洩客戶數據？ | Token 存在 Streamlit Cloud 的 Secrets，不寫在程式碼裡；數據只在自己帳號權限範圍內讀取，不會存到第三方。 |
| 直接改預算會不會誤觸、改錯？ | 有勾選確認機制，調整前會列出選中的活動清單，確認幅度後才送出；每次調整都會顯示「舊預算→新預算」的結果，可回頭核對。 |
| 其他部門/同事能用嗎？ | 目前是為 Meta 廣告帳戶設計，只要換帳戶 ID 跟 Token 就能套用；如果有興趣我可以幫忙串接。 |
| 跟現有工具（Ads Manager）差在哪？ | Ads Manager 一次只能看/改一個活動，這邊是多活動一次看、一次批次調整，還自動幫你依今日表現排序，省掉來回切換、手動比較的時間。 |
| 開發花了多久／用什麼工具做的？ | 用 Streamlit + Python，搭配 Claude Code 協作開發，前後迭代大概 [填：實際時間]。 |

## 四、上台前檢查清單
- [ ] 現場網路確認可用（demo 需要即時打 Meta API，且「快速加減碼」是真的會改動後台預算，要確認示範的帳戶/活動可以真的調整或先想好要調哪個測試活動）
- [ ] Streamlit app 帳號/Token 確認未過期（app 內有到期提醒，上台前先看一次）
- [ ] 備援方案：先錄一段 30-60 秒的操作畫面截圖/GIF（尤其是「快速加減碼」按下去瞬間變化的畫面），若現場斷網可切換播放
- [ ] 先想好示範時要調整哪個活動、調多少 %，避免臨場誤改到不該動的活動預算
- [ ] 瀏覽器分頁先開好、放大字體，確認投影時看得清楚
- [ ] 手機計時器，抓 2:30 進效益總結，避免超時
- [ ] 效益數字已確認：一週省下 1~1.5 小時

1. Q&A 小抄裡「開發花了多久」還有 **[填：實際時間]** 佔位，如果評審可能會問可以先想好答案。
